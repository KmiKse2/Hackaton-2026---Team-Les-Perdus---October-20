SIGNAL CATALOG FOR KBC LIFEFLOW

1. age_group
Source:
- Customer identity / KYC data

How to obtain:
- Read customer date_of_birth
- Convert into age range, for example:
  18-25
  26-35
  36-50
  51-65
  65+

Type:
- Declared / verified

Recommended confidence:
- 1.0


2. employment_status
Source:

Possible values:
- student

- unemployed

How to obtain:
- Read directly from customer profile when available
- Do not infer as fact if not declared

Type:
- Declared

Recommended confidence:
- 1.0 if explicitly declared
- otherwise null / unknown

5. monthly_income
Source:
- Incoming transactions
- Customer-declared income

How to obtain:
- Detect recurring incoming payments
- Group by sender / payment description
- Calculate average monthly amount over last N months

Example logic:
- salary payments detected 3 months in a row
- average = 2650 EUR

Type:
- Observed or declared

Recommended confidence:
- 0.95 if recurring transaction pattern
- 1.0 if verified/declaration used


6. income_change_percentage
Source:
- Transaction history

How to obtain:
- Compare average income over recent period versus previous period

Formula:
(current_avg_income - previous_avg_income)
/ previous_avg_income * 100

Type:
- Derived

Example:
+320%

Recommended confidence:
- 1.0 because it is mathematically derived

--------------------------------
age_group
employment_status

-------------------------------

-------------------------
income_change_percentage

LEVEL 4 — INFERRED CUSTOMER STATE
---------------------------------
student
young_professional
first_job
moving
home_purchase
travelling
financial_stress
wealth_growth


IMPORTANT IMPLEMENTATION RULE

Never store an inferred customer state as if it was a verified fact.

Every inferred signal must contain:
- value
- confidence
- source
- timestamp
- status

Customer confirmation through Kate should override the inference.
